# 52pj 架构设计

> 只读浏览 52pojie.cn 的命令行工具。本文讲**怎么搭的**；功能与用法见
> [功能设计.md](功能设计.md)。

## 1. 目标与约束

52pojie.cn 是 Discuz X3 论坛，站点特征决定了整个架构：

| 站点特征 | 对架构的要求 |
|---|---|
| TLS 层有风控，裸 TLS 指纹会被识别 | 所有 HTTP 必须走 `curl_cffi` 的 Chrome 指纹，不提供 requests 降级 |
| 页面是 GBK 编码 | 正文按原始字节取回再本地解码，不能让浏览器/库猜编码 |
| 登录 cookie 是 HttpOnly | 本地进程读不到完整串，只能借浏览器的 cookie 容器发请求 |
| 登录要过 Cloudflare Turnstile | 无法纯脚本过验证，登录必须由人完成 |
| 楼号是 JS 渲染的 HTML 里没有 | 楼号按 DOM 顺序推算 |
| 站内搜索 `search.php` 302 到 Bing | 搜索改走外部引擎 + 本地过滤兜底 |

约束直接写进代码：`curl_cffi` 缺失时 `raise SystemExit(2)`，不做静默降级。

## 2. 分层

```
                    ┌───────────────────────────────┐
   CLI 层           │  pojie.py  命令解析 / 上下文 / 输出 │
                    └───────────────┬───────────────┘
                                    │
                    ┌───────────────▼───────────────┐
   会话层           │  Client   cookie 持久化 / 限速 / 指纹 │
                    └───────────────┬───────────────┘
                                    │
              ┌─────────────────────┼─────────────────────┐
              │                     │                     │
    ┌─────────▼────────┐  ┌─────────▼────────┐  ┌────────▼─────────┐
    │ transport=curl    │  │ backend=webview  │  │ backend=browser  │
    │ curl_cffi 直连    │  │ App 内 WebView    │  │ 本机浏览器        │
    │ 带本地 cookie 库   │  │ 借 App 的 cookie   │  │ Playwright 驱动   │
    └──────────────────┘  └──────────────────┘  └──────────────────┘
              │                     │                     │
              └─────────────────────┴─────────────────────┘
                                    │
                    ┌───────────────▼───────────────┐
   解析层           │  BeautifulSoup  板块/帖子/楼层解析 │
                    └───────────────────────────────┘
```

三种传输层实现同一个接口（`get` / `request` / `headers` / `cookies`），
上层命令代码不感知当前用的是哪一种。

## 3. 传输层三态

### 3.1 curl 直连（默认）

`curl_cffi.requests.Session(impersonate="chrome")`，UA 与 TLS 指纹成对自动对齐
（手改 UA 反而和指纹矛盾）。cookie 存本地 SQLite。

### 3.2 WebView 后端（App / 沙箱内）

借 Minis App 内的 WebView 发请求。同源 `fetch` 自动带上 App 的 HttpOnly cookie
——这是唯一不需要手工复制 cookie 的路子。

实现要点：
- 正文按原始字节取回再 base64 传回，**不能走 `text()`**，否则 GBK 中文乱码；
- 只有前台标签页不会被 WebView 冻结，后台标签里 `fetch` 和定时器一起挂起
  （表现为 30 秒超时），所以要保证浏览器停在本站；
- 活动标签的 `*` 标记在**行尾**（`  Tab 0: 标题 — url *`），不在行首——
  这是踩过的坑，`_TAB_RE` 必须按行尾匹配。

### 3.3 本机浏览器后端（桌面端）

Playwright 驱动**系统已安装**的浏览器，`executable_path` 指向真实 exe。
不下载浏览器、不需要 chromedriver、不往代码目录写任何驱动文件。

浏览器定位分两层：

1. **系统默认浏览器**：读注册表 `UserChoice` 的 ProgId，再顺着
   `HKCR\<ProgId>\shell\open\command` 找到那个 exe。
   只有走这一层才对——同一台机器可能装着多个 Chrome（不同盘、不同版本），
   而 ProgId 只说明「是哪家浏览器」，不指明是哪一个。
2. **兜底候选**：注册表 `App Paths` → 常见安装目录 → `PATH`。

登录态由本机浏览器的 profile 目录携带（`~/.52pj/browser-profile`），
`auth` 与 `-b` 共用同一个 profile。

### 3.4 无头模式与 UA 保真

读操作默认无头（`headless=True`），只有 `--headed` 才开窗。
**登录恒定有头**：`auth` 走 `open_login_window()`，`login -u/-p` 也是，
因为人机验证（Cloudflare Turnstile）必须有人点。

难点是 UA。Chrome 的 `--headless`（含新版 `--headless=new`）会把 UA 里的
`Chrome/x` 改成 `HeadlessChrome/x`，等于自报机器人。实测四种组合
（Playwright 的 `headless=True/False` × 手动传/不传 `--headless=new`）
**全部**是 `HeadlessChrome`——这是 Chrome 自身行为，无法靠启动参数绕过。

所以启动时显式覆盖：

1. 从浏览器安装目录的版本子目录（`Application/138.0.7204.101/`）取主版本号；
2. 按平台模板拼出正常 UA（`Chrome/138.0.0.0`，只用主版本 + `.0.0.0`）；
3. 传给 `launch_persistent_context(user_agent=...)`。

覆盖后三项完全一致（实测）：

| 项 | 有头 | 无头（覆盖后） |
|---|---|---|
| `navigator.userAgent` | `Chrome/138.0.0.0` | `Chrome/138.0.0.0` |
| HTTP `User-Agent` | 同上 | 同上 |
| `sec-ch-ua` | `v="138"` | `v="138"` |

WebView 后端不需要处理：它是 App 内嵌的真 Chromium（实测 142），
UA 天然正常，且 fetch 在页面上下文发起，UA 由 App 决定，不经过我们的代码。

### 3.5 为什么不用 Selenium

Selenium 需要 chromedriver，且驱动大版本必须与浏览器严格一致
（否则 `session not created`）。Selenium Manager 要联网去
`googlechromelabs.github.io` 抓版本——国内连不上（实测 `os error 10054`），
失败后还会把驱动下载到**当前工作目录**，污染代码仓库。

Playwright 直接用 `executable_path` 指向已装的浏览器，整条链路绕开了。

## 4. 后端选择

```
-b / --browser      自动：有 minis-browser-use 通道就用 WebView，否则本机浏览器
-W / --webview      强制 App 内 WebView（条件不具备直接报错，不静默换后端）
-L / --local        强制本机默认浏览器
（都不给）           curl 直连
```

三个开关是并列关系，不是三选一的枚举——`-b` 是「借道浏览器」的总开关，
`-W` / `-L` 是对它的进一步限定。`--webview` 与 `--local` 互斥。

## 5. 反反爬

- **请求间隔**：每次请求在 `[0.7, 1.3]` 秒间随机取值，避免固定节奏；
- **Chrome 指纹**：`curl_cffi` 的 `impersonate`，UA 与 client hints 成对带出；
- **Referer 滚动**：记住上一页 URL 作为下一页 Referer，同源跳转带 `Referer`；
- **跨域标记**：外部搜索引擎请求走 `external=True`，不污染 `last_url`，
  `Sec-Fetch-Site` 标成 `cross-site`；
- **429 退避**：等 10 秒重试，最多 3 次。

## 6. 状态与存储

SQLite（`~/.52pj/52pj.db`）存 cookie、选择状态、列表缓存；
`~/.52pj/state.json` 存当前选中的板块/帖子。

选择状态跨命令、跨会话保留，规则是**显式参数 > select 选择**，
执行成功后结果自动记为当前选择；`--keep` 可以临时看一眼而不改动选择。

## 7. 模块划分

| 文件 | 职责 |
|---|---|
| `pojie.py` | 命令解析、各子命令、上下文管理、请求编排 |
| `_ui.py` | 表格渲染、颜色、宽度自适应、JSON 输出 |
| `_store.py` | SQLite 读写、cookie 持久化、列表缓存 |
| `_pager.py` | 交互式阅读器（方向键/PgUp·PgDn，Windows 用 msvcrt，Unix 用 termios） |
| `_browser.py` | WebView 后端（`minis-browser-use` 桥接） |
| `_browser_local.py` | 本机浏览器后端（Playwright） |
| `_enc.py` | 终端编码自适应 |

## 8. 编码处理

Windows 上 Python 重定向到文件/管道时 stdout 跟随系统 ANSI 代码页
（zh-CN 是 cp936/GBK），在真正支持 UTF-8 的终端里中文会乱码。

策略：

1. stdout 已是 UTF-8（Python 3.6+ 直连控制台时就是）→ 原样不动；
2. 重定向到文件/管道 → 写**纯 UTF-8，不带 BOM**（`utf-8` 而非 `utf-8-sig`）；
3. 交互终端 → 尝试把控制台切到 65001，切不动退回系统编码（GBK 在老 cmd 里是对的）；
4. 兜底 `errors="replace"`，任何情况下都不因编码抛 `UnicodeEncodeError`。

`52PJ_ENCODING=utf-8|native|gbk` 可强制。

## 9. 工程决策与踩坑记录

| 坑 | 表现 | 解法 |
|---|---|---|
| Selenium Manager 连不上 | 驱动下载失败，且落到工作目录 | 换 Playwright |
| 驱动大版本不匹配 | `session not created` | 不再用驱动 |
| WebView 活动标签 `*` 在行尾 | 判定「无前台标签」→ 反复 new_tab → 撞 3 标签上限 | 正则改按行尾匹配 |
| `pyproject.toml` 漏模块 | pip 安装版 `import _enc` 失败 → 编码自适应整段跳过 → `✗` 编不出直接崩 | `py-modules` 补齐 |
| `py` 启动器不存在 | bat 里 `py -3 ... & exit /b` 无条件链式，第一行失败就退出 | 改成逐个 `where` 探测 |
| 硬编码 `"/x"` 路径断言 | 测试在 Windows 上必然失败 | 改用 `os.path.join` |
| `pip install .` 联网拉 setuptools | 国内 DNS 解析失败 | 换清华镜像 |
